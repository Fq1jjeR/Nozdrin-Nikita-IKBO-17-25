# Инструмент визуализации графа зависимостей (Cargo)

Проект по дисциплине «Конфигурационное управление», ПР №2, вариант 17.
Инструмент строит граф зависимостей для пакетов формата **Cargo (Rust)**
и визуализирует его с помощью Graphviz.

## Общее описание

Инструмент получает прямые зависимости пакета Cargo по URL репозитория
(или из файла тестового репозитория), строит транзитивный граф зависимостей
алгоритмом BFS без рекурсии, поддерживает обратные зависимости и сохраняет
изображение графа в формате PNG через Graphviz.

Запрещено использовать готовые менеджеры пакетов и сторонние библиотеки
для получения информации о зависимостях: разбор `Cargo.toml` и HTTP-запросы
реализованы средствами стандартной библиотеки Python (`urllib`, `re`,
`argparse`, `collections`, `subprocess`).

## Настраиваемые параметры

Источник параметров — опции командной строки (вариант 17).

| Опция           | Кратко | Описание                                          | По умолчанию |
|-----------------|--------|---------------------------------------------------|--------------|
| `--package`     | `-p`   | имя анализируемого пакета                          | — (обязателен) |
| `--repo`        | `-r`   | URL репозитория или путь к файлу тестового репозитория | — (обязателен) |
| `--test-mode`   | `-t`   | режим работы с тестовым репозиторием               | `False`      |
| `--output`      | `-o`   | имя сгенерированного файла с изображением графа     | `graph.png`  |
| `--max-depth`   | `-d`   | максимальная глубина анализа зависимостей          | `10`         |
| `--mode`        | `-m`   | режим работы: `config`, `deps`, `graph`, `reverse`, `viz` | `config` |

## Описание функций и настроек

### `src/config.py` — конфигурация (этап 1)

- `AppConfig` — dataclass с параметрами приложения.
- `parse_args(argv)` — разбор и валидация аргументов командной строки.
- `validate_package(name)` — проверка имени пакета (буквы, цифры, `_`, `-`).
- `validate_output(filename)` — проверка имени выходного файла.
- `validate_repo(repo, test_mode)` — проверка URL или пути к файлу.
- `validate_max_depth(value)` — проверка глубины (1–100).
- `format_config(config)` — форматирование параметров как `ключ=значение`.

### `src/collector.py` — сбор данных (этап 2)

- `fetch_text(url)` — получение текста по URL через `urllib`.
- `read_file(path)` — чтение локального файла.
- `github_raw_candidates(repo_url)` — построение URL для веток `main`/`master`.
- `get_cargo_toml(config)` — получение содержимого `Cargo.toml`.
- `parse_dependencies(toml_text)` — разбор секций `[dependencies]` и
  `[dependencies.name]` (inline-таблицы).
- `get_direct_dependencies(config)` — список прямых зависимостей пакета.

### `src/graph.py` — построение графа (этап 3)

- `parse_test_repo(text)` — разбор файла тестового репозитория
  (формат `PACKAGE: dep1, dep2, ...`).
- `TestRepoProvider` / `UrlProvider` — поставщики зависимостей.
- `build_graph_bfs(config, provider)` — BFS без рекурсии через `deque`,
  с учётом `max_depth` и обработкой циклов через множество `visited`.
- `get_graph(config)` — граф, достижимый из корневого пакета.
- `get_full_graph(config)` — полный граф всех пакетов репозитория.

### `src/analyzer.py` — обратные зависимости (этап 4)

- `build_reverse_graph(graph)` — инверсия рёбер графа.
- `find_reverse_deps(graph, target)` — BFS без рекурсии на обращённом
  графе; возвращает пакеты, зависящие от `target`.
- `get_reverse_dependencies(config)` — обратные зависимости пакета.

### `src/visualizer.py` — визуализация (этап 5)

- `to_dot(graph, root)` — формирование описания графа на языке DOT.
  Корневой пакет выделяется цветом.
- `render_png(dot_text, output_file)` — генерация PNG через утилиту `dot`.
- `build_visualization(config)` — построение DOT и сохранение PNG.

## Сборка и запуск

Требуется Python 3.10+ и утилита `dot` из пакета Graphviz (для этапа 5).

```bash
# Запуск приложения
./run.sh -p <пакет> -r <url|путь> -m <режим> [опции]
```

## Запуск тестов

```bash
python3 -m unittest discover -s tests -v
```

## Примеры использования

### Этап 1: вывод параметров

```bash
./run.sh -p serde -r https://github.com/serde-rs/serde -m config
```

### Этап 2: прямые зависимости

```bash
# Тестовый файл Cargo.toml
./run.sh -p sample -r examples/sample_cargo.toml -t -m deps

# Реальный репозиторий
./run.sh -p regex -r https://github.com/rust-lang/regex -m deps
```

### Этап 3: граф зависимостей

```bash
# Линейный граф
./run.sh -p A -r examples/test_repo_linear.txt -t -m graph

# Циклический граф (цикл обрабатывается корректно)
./run.sh -p A -r examples/test_repo_cycle.txt -t -m graph

# Ограничение глубины
./run.sh -p A -r examples/test_repo_deep.txt -t -m graph -d 2
```

### Этап 4: обратные зависимости

```bash
# Кто зависит от D в ромбовидном графе
./run.sh -p D -r examples/test_repo_diamond.txt -t -m reverse
```

### Этап 5: визуализация

```bash
# Линейный граф → PNG
./run.sh -p A -r examples/test_repo_linear.txt -t -m viz -o linear.png

# Ромбовидный граф → PNG
./run.sh -p A -r examples/test_repo_diamond.txt -t -m viz -o diamond.png

# Циклический граф → PNG
./run.sh -p A -r examples/test_repo_cycle.txt -t -m viz -o cycle.png

# Реальный репозиторий
./run.sh -p regex -r https://github.com/rust-lang/regex -m viz -o regex.png
```

## Формат тестового репозитория

Тестовый репозиторий — текстовый файл, где каждая строка описывает
пакет и его прямые зависимости:

```
# комментарий (игнорируется)
PACKAGE: dep1, dep2, dep3
```

Пакеты называются большими латинскими буквами (A, B, ..., Z).
Пустой список зависимостей допустим (`D:` без значений).

Пример (ромбовидная зависимость):

```
A: B, C
B: D
C: D
D:
```

## Сравнение с штатными инструментами

Штатный инструмент визуализации зависимостей Cargo — `cargo tree`.
Он выводит дерево зависимостей локального пакета на основе
`Cargo.lock` и реестра `crates.io`.

### Различия

| Аспект | Наш инструмент | `cargo tree` |
|--------|----------------|--------------|
| Источник данных | `Cargo.toml` по URL репозитория | Локальный `Cargo.lock` + реестр |
| Транзитивные зависимости | Полные в тестовом режиме; прямые в URL-режиме | Полные, через реестр `crates.io` |
| Версии | Не разрешаются (только имена) | Разрешаются через `Cargo.lock` |
| Workspace-зависимости | Не разрешаются (`name.workspace = true`) | Разрешаются через `[workspace.dependencies]` |
| Вывод | Граф на DOT + PNG | Текстовое ASCII-дерево |
| Циклы | Обрабатываются через множество `visited` | Обрабатываются |

### Причины расхождений

1. **Транзитивные зависимости в URL-режиме.** Методичка запрещает
   использование менеджеров пакетов и сторонних библиотек для получения
   зависимостей. Для разрешения транзитивных зависимостей по имени
   пакета требуется реестр (`crates.io` API), что нарушает ограничения.
   Поэтому в URL-режиме разрешаются только прямые зависимости. В
   тестовом режиме транзитивные зависимости разрешаются полностью,
   так как весь граф задан в файле.

2. **Workspace-зависимости.** Современные репозитории Cargo используют
   формат `[dependencies.name]` (inline-таблицы) и `name.workspace = true`.
   Наш парсер поддерживает inline-таблицы, но не разрешает ссылки на
   `[workspace.dependencies]`, так как это требует анализа нескольких
   файлов `Cargo.toml` в иерархии workspace.

3. **Версии.** `cargo tree` разрешает конкретные версии через
   `Cargo.lock`, тогда как наш инструмент работает с именами пакетов
   без привязки к версиям, что соответствует задаче визуализации
   структуры графа зависимостей.
